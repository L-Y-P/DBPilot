## 界面总览

```text
┌───────────────────────────────────────────────────────────────────────────┐
│ DBPilot   [驱动徽标] 连接名 @账号      连接管理 查询构建器 SQL控制台 服务器 工具v  ⚙ │
├───────────────┬───────────────────────────────────────────────────────────┤
│ 数据库树        │ 当前页面                                                  │
│  ├ 库 / 模式    │  （连接管理 / 库页 / 表页 / 构建器 / 控制台 / 服务器 …）     │
│  │   ├ 表       │                                                          │
│  │   └ 视图 …   │                                                          │
│  └ …            │                                                          │
└───────────────┴───────────────────────────────────────────────────────────┘
```

- **顶栏**：产品名、当前连接（驱动 / 名称 / 账号）、五个导航入口、齿轮（设置）。
  未连接时导航项变灰，只有"连接管理"可用。
- **左侧树**：库 / 模式 → 表。SQLite 连接按**目录**分组，组内是每个文件（主文件带 `DB` 徽标，
  当前库带"默认"标记）。
- **右侧**：当前页面。表页内部还有九个页签。
- 窗口尺寸会被记住（最小 960×600）；顶部栏与侧栏宽度固定，页面区域自适应。

## 连接管理

### 新建 / 编辑连接

右上角 **新建连接**（或连接卡片上的 **编辑**）打开连接编辑器。表单分三个页签：

**常规**

| 字段 | 说明 |
| --- | --- |
| 驱动 | MySQL / MariaDB、PostgreSQL、SQLite |
| 连接名 | 卡片与顶栏显示的名字 |
| 主机 / 端口 / 用户名 / 密码 | MySQL / PostgreSQL 用；PostgreSQL 的主机可填 Unix socket 目录（如 `/tmp`） |
| 数据库（可选） | 留空则连接后自动选择第一个可访问的库 |
| 连接字符集 | 仅 MySQL；按客户端能力表校验（`utf8mb3` 会映射为 `utf8`） |
| 仅显示数据库 | 逗号分隔，可写通配符（`db1,db2`） |
| 隐藏数据库 | 逗号分隔，可写通配符（`test%,tmp%`） |
| 颜色 | 连接卡片与树节点的标识色 |
| 数据库文件 / 数据库目录 | 仅 SQLite：主文件 + 要递归扫描的目录（留空 = 主文件所在目录） |

**SSL**

- MySQL：`SSL 模式`（disable / require / verify-ca / verify-full）+ `证书校验`，
  可指定 **CA 证书**、**客户端证书**、**客户端私钥**（mTLS）。
- PostgreSQL：`SSL 模式（libpq）`（disable / require / verify-ca / verify-full），同样可配 CA 与客户端证书。
- SQLite 没有网络连接，这一页只显示说明。

**SSH**（跳板机）

| 字段 | 说明 |
| --- | --- |
| 通过 SSH 隧道连接 | 开关 |
| SSH 主机 / 端口 / 用户名 | 跳板机地址，端口默认 22 |
| 认证方式 | 密码 / 私钥文件 / ssh-agent |
| SSH 密码 / 私钥口令 | 密码认证的密码，或加密私钥的口令 |
| 私钥文件 | OpenSSH / PEM 私钥 |
| agent 套接字 | 留空使用 `SSH_AUTH_SOCK` |
| 主机密钥策略 | 首次连接信任并记住（默认）/ 仅信任已保存指纹 |
| 主机密钥指纹 | `SHA256:...`，首次"测试连接"成功后自动回填，也可手动粘贴 |

> **语义提醒**：开了 SSH 之后，"常规"页里的**主机是跳板机视角的数据库地址**。
> 所以填 `127.0.0.1:3306` 表示"跳板机本机上的 MySQL"；填内网地址表示"跳板机能访问的内网库"。
> 本地只在 `127.0.0.1` 的临时端口监听，不会把数据库端口暴露到你的局域网。

底部两个按钮：

- **测试连接**：真实连一次（含 SSH 握手 / TLS 握手），结果显示在对话框内；
- **保存**：写入 `connections.json`（0600）。

### 打开与断开

- 连接卡片上的 **打开**：建立连接、探测版本、按 `only_db` / `hide_db` 选择初始库。
  连接过程有进度提示：**第 5 秒**起显示"已用时 N 秒 · 网络较慢"和**取消**按钮；
  取消后晚到的结果会被丢弃。
- 已连接时页面顶部显示"当前连接：…"，旁边是 **断开连接**。
- 连接被删除、配置损坏或目录不可读时，卡片会显示对应提示；损坏的连接文件会**原样保留**
  成备份，不会被空列表覆盖。

### SQLite 的特殊数据模型

**一个 SQLite 连接 = 一个目录**，不是一个文件：

- 连接时递归扫描目录（`.sqlite / .sqlite3 / .db / .db3`，最多 500 个文件 / 6 层）；
- 主文件是 `main`，其余文件逐个 `ATTACH` 成别名（SQLite 默认上限 10 个，多出来的会提示"另有 N 个未打开"）；
- 不记录文件列表：**目录就是状态**，在目录里增删文件后点侧栏的 **刷新** 即可；
- 侧栏按目录分组；"打开目录"按钮在系统文件管理器里定位该目录。

## 库与对象浏览

点侧栏的库 / 模式进入库页：

- **数据表**卡片：表名、类型（BASE TABLE 等）、**行数（估算）**、大小、备注、
  清空 / 删除；**每页 50 条**，底部翻页。
- **对象**卡片：视图、存储过程 / 函数、触发器、事件四个子页签，每页 50 条，
  可搜索、刷新、**新建对象**（填名称与定义，拒绝多语句定义）、查看定义、删除。
- 顶部按钮：**新建表**、**新建模式**（PostgreSQL）、**删除数据库 / 模式**、**刷新**、**打开目录**（SQLite）。
- SQLite 的行数列是精确的 `COUNT(*)`；MySQL / PostgreSQL 是服务端统计值，
  可能和"浏览"页的实时行数不同（界面上有说明）。

> 权限：MySQL 的可浏览库由 `SHOW GRANTS` 推导；PostgreSQL 用
> `has_schema_privilege(USAGE)` / `has_database_privilege(CONNECT)` 过滤。
> 看不到某个库不是 bug，而是当前账号确实没有权限；对象被过滤时会提示"已按权限隐藏 N 个对象"。

## 表页九个页签

点侧栏的表进入表页。表页顶部显示"库 / 表"，右侧是行数徽标与 **返回**。

| 页签 | 内容 |
| --- | --- |
| **浏览** | 数据网格（见下） |
| **结构** | 字段列表（类型、NULL、默认值、键、注释、额外信息） |
| **设计** | 可视化 ALTER：表选项、字段设计、索引、外键 + **SQL 预览** + **应用修改** |
| **DDL** | 服务端真实建表语句（`SHOW CREATE TABLE` / `pg_get_tabledef` / `sqlite_master`） |
| **插入** | 逐字段填值插入一行（留空使用默认值） |
| **SQL** | 表级 SQL 控制台，默认带 `USE 库名;`（MySQL）/ `SET search_path TO "schema";`（PostgreSQL） |
| **导出** | 8 种格式，可勾选包含结构 / 数据 / DROP，支持预览 |
| **导入** | 进入数据导入向导（见下） |
| **操作** | 清空表 / 删除表（视图不可用） |

### 浏览（数据网格）

工具栏从左到右：

- **列 (13/13)**：勾选要显示的列；
- **筛选** 图标：逐列筛选输入框；
- **复制选中 / 删除选中**：先勾选行（最左侧复选框）；
- **每页**：25 / 50 / 100 / 250；
- **刷新**；
- **导出 CSV / 导出 JSON**：快速导出当前视图。

网格交互：

- **单击表头排序**，**Shift + 单击**追加第二、第三排序键；表头显示排序序号。
- **单击单元格复制内容**；**双击**打开完整内容（大字段尤其有用）。
- **单元格编辑**：能定位主键时（单表 SELECT），双击打开编辑弹窗，可勾 `NULL`，
  点「保存」写回数据库；弹窗里也有"复制内容"按钮。
- 横向滚动条固定在视口底部（不用滚到最后一行才能左右拖）。

分页采用 **keyset 游标**：单列主键 + 主键升序时走 `WHERE pk > cursor` 索引范围扫描，
比 `OFFSET` 在大表上快得多；复合主键 / 无主键 / 按其它列排序会自动回退到 `OFFSET`。
游标页默认**不发 `COUNT(*)`**（行数徽标沿用第一页的统计值），写操作或手动刷新时才重算。

### 设计（可视化 ALTER）

1. **表选项**：重命名为、表注释；
2. **字段设计**：字段名 / 类型 / 允许 NULL / 默认值 / 自增 / 备注，可增删字段；
3. **索引**：索引名、唯一、列；可添加；
4. **外键**：名称、列、引用表、引用字段、删除时 / 更新时动作（SQLite 不支持，会明确提示）；
5. 点 **预览 SQL** 看将要执行的 `ALTER TABLE` 语句，确认后点 **应用修改**。

默认值会做安全校验（拒绝分号、注释符等语句终止符并校验引号配对），
不会把用户输入原样拼进 DDL。

## SQL 控制台

顶栏 **SQL 控制台**（需要先连接）。默认内容是 `SELECT 1;`，**不会自动注入 `USE` 库名**。

工具栏：

| 按钮 | 说明 |
| --- | --- |
| **执行** | 执行全部语句（`Cmd/Ctrl + Enter` 同效） |
| **取消** | MySQL 走 `KILL QUERY`；PostgreSQL 走 `pg_cancel_backend`；SQLite 在进程内执行，无法安全取消（按钮有说明） |
| **清空** | 清空编辑器 |
| **EXPLAIN** | 对**第一条**语句执行 EXPLAIN（已写 EXPLAIN 时不会重复加前缀；SQLite 用 `EXPLAIN QUERY PLAN`） |
| **历史记录** | 跳到查询历史页 |
| **导入 SQL 文件** | 小文件载入编辑器；大文件可选"载入前 128 KB"或直接流式执行 |
| **执行 SQL 文件** | 选 `.sql` 文件从磁盘**逐条流式执行**（不载入内存，可取消，失败报位置） |

特性：

- **语法高亮**：关键字 / 字符串 / 注释 / 数字 / 标识符 / 运算符；文件大于 120 KiB 时退化为纯文本防卡顿。
- 多语句用分号分隔，结果按语句分组，每组显示耗时与语句数。
- 单次查询结果上限 **50 000 行**，超出会截断并提示（建议加 `WHERE` / `LIMIT` 或到表页导出）。
- 结果表**每页 50 行**，可导出（与表页同一套 8 种格式）。
- 结果表在单表 SELECT 且能定位主键时可**行内编辑**。

## 查询构建器

顶栏 **查询构建器**（需要先连接）。适合"不手写 SQL 也能拼出 JOIN"的场景。

布局：

- **左侧数据源树**：库 / 模式 → 表 → 字段。点字段加入"输出字段"，点表设为主表。
- **右上工作区四个页签**：
  - **输出字段**：已选字段、聚合（COUNT / SUM / AVG / MIN / MAX）、别名、去重；
  - **连接关系**：JOIN 类型（INNER / LEFT / RIGHT / FULL）与 ON 条件；
  - **筛选条件**：条件行、AND 组、OR 组；
  - **排序**：多列升 / 降序。
- **SQL 预览条**：实时显示将要执行的 SQL，可展开 / 收起 / 复制。
- **结果预览**：执行后显示前 N 行，**每页 50 行**，可导出 8 种格式。

要点：

- **多方言**：MySQL / PostgreSQL / SQLite 各自适配。比如 PostgreSQL 原生 `FULL OUTER JOIN`，
  MySQL 用 UNION 改写；MySQL 生成不了合法 SQL 时（两分支表集合不一致、多个全连接）会降级为
  LEFT JOIN 并给出 warning，**绝不生成非法 SQL**。
- **中文界面下 SQL 关键字按语义显示**（"等于（=）"、"IS NULL → 为空"、"LEFT → 左连接"），
  英文界面保持原始 SQL 词；预览与最终执行的 SQL 始终是标准 SQL。
- **跨库查询**：**高级查询**里可勾选其它库 / 模式的表（不会重置当前配置），
  跨库的 ON 条件需要手动指定（无法自动推导外键）。
- **保存为查询模块**：把当前配置存成文件，之后"打开查询模块"恢复。
- 参数化预览里的占位参数在执行前会按驱动规则**安全转义**为字面量。

## 数据导入向导

表页 **导入** 页签 → **打开数据导入向导**。四步，每一步通过校验才能进入下一步。

### 第 1 步：选择文件

选文件后自动**按扩展名 + 内容特征识别格式**（可手动改）：

| 格式 | 识别判据 |
| --- | --- |
| Excel（`.xls`，SpreadsheetML） | 扩展名 `.xls` 或内容含 `mso-application progid="Excel.Sheet"`（先于 XML 判断） |
| XML | 扩展名 `.xml` 或内容以 `<?xml` / `<rows` 开头 |
| HTML 表格 | 扩展名 `.html/.htm` 或内容以 `<!doctype` / `<table` 开头 |
| Markdown 表格 | 扩展名 `.md/.markdown`，或首行是竖线表格行、第二行是 `---` 分隔行 |
| JSON 数组 / JSON Lines | 首字符 `[` 为数组；每行一个 `{` 为 Lines |
| 分隔文本 | 其余情况（CSV / TSV / 任意分隔符） |

编码只支持 **UTF-8（含 BOM）**；UTF-16 / GBK 会明确报错并提示另存为 UTF-8。

> 向导处理的是**记录型**格式（上表 7 种）。`.sql` 脚本不是"记录 → 行"的映射，
> 请用表页的"执行 SQL 文件"或 SQL 控制台的"执行 SQL 文件"（流式逐条执行，可取消）。

### 第 2 步：读取规则（一条完整数据怎么切分）

- **记录方式**：每行一条记录，或"包裹符 + 记录分隔符"；
- **记录分隔符**（默认 `\n`）、**引号字符**（默认 `"`）、**跳过空行**、**去除首尾空白**；
- 结构化格式（XML / HTML / Excel / Markdown）会自动填好终止符与记录分隔符，
  通常不需要改；
- 点 **预览第一条**：回显"表头"与切分出的第一条记录（第 N 条、字节位置），
  确认规则对得上再点 **开始校验**（整文件校验，报告"第 N 行（第 X 条，字节 Y）：原因"）。

### 第 3 步：字段与映射

- **字段方式**：
  - `JSON（对象=列名，数组=按位置）`；
  - `分隔文本（可勾选首行为列名）`；
  - 结构化格式按标签 / 单元格解析；
- **字段规则**：分隔符、引号、NULL 标记（默认 `\N`，逗号分隔多个）、括号层级识别；
- **列映射**：把文件字段映射到目标表的列，可忽略多余字段；
- **试插入**：事务内 `INSERT` 一条 → 回读样例行 → `ROLLBACK`，回显生成的 SQL 与转换后的列值。
  这是"规则对不对"的最后一道验证。

### 第 4 步：执行导入

- 可选 **导入方式**、**批量大小**（默认 500 行/批）、**出错处理**（停止并报告位置）；
- 进度按已读字节 / 已写入行数显示，**随时可取消**；
- 完成后显示写入行数、失败行数与耗时。

> **重要**：导入是**分批提交**的。取消或中途失败时，**已经提交的批次会保留**，
> 不会自动回滚。大文件建议先在事务外的测试表上跑一遍。

NULL 与空字符串在所有格式里都可区分：

| 格式 | NULL | 空字符串 |
| --- | --- | --- |
| CSV / TXT / Markdown | `\N` | 空 |
| XML | `<col name="x" null="true"/>` | `<col name="x"></col>` |
| HTML | `<td class="null"></td>` | `<td></td>` |
| Excel | `<Cell/>` | `<Cell><Data ...></Data></Cell>` |
| JSON | `null` | `""` |
| SQL | `NULL` | `''` |

## 导出

三个入口，共用同一套 writer：

1. **表页 → 导出**：选格式；SQL 格式还可勾选 **包含结构 / 包含数据 / 包含 DROP**；
   可先 **预览** 再 **导出到文件**（系统保存对话框）。
2. **表页浏览工具栏**：**导出 CSV / 导出 JSON** 快速导出当前视图。
3. **SQL 控制台 / 构建器的结果卡片 → 导出结果**：导出当前结果集。

**8 种格式**：SQL、CSV、JSON、XML、HTML、TXT、Excel（`.xls`，SpreadsheetML 2003）、Markdown。

- 导出是**流式**的（`ExportStream`），大表不会整体进内存；
- 每行严格输出 N 个单元格（短行按 NULL 补齐），所以导出的文件能原样导回来；
- 真正的 `.xlsx`（ZIP + OOXML）不支持，请选 `.xls` 或 CSV。

## 备份与恢复

顶栏 **工具 → 备份**（需要先连接）。

- 顶部显示当前备份目标数据库；MySQL 选"数据库"、PostgreSQL 选"模式"，
  再用"表"下拉框选单表（留空 = 整库 / 整个模式）；
- **备份**：把库或表 dump 成 `.sql`（带头部元信息：驱动、数据库、时间），
  文件名做了跨平台安全处理（Windows 保留设备名 / 非法字符都会被替换）；
- 列表每页 20 条，可按驱动筛选；每条有 **另存为 / 恢复 / 删除**；
- **恢复**前会确认，完成后报告执行了多少条语句；
- 备份目录默认是数据目录下的 `backups/`，可在 **设置 → 备份** 里改到别处（立即生效）。

> 备份文件是普通文本 SQL，也可以直接用命令行 `mysql < file.sql` 恢复。

## 结构比对与同步

顶栏 **工具 → 结构同步**（需要先连接）。

1. 选 **源数据库 / 模式** 与 **目标数据库 / 模式**（不能相同；PostgreSQL 可选同一库的不同模式）；
2. 可选 **仅比对某张表**、**允许删除目标中多余的字段 / 索引**；
3. 点 **开始比对**：逐表给出状态（结构一致 / 目标缺失 / 有差异）与将要执行的 DDL；
4. 点 **执行同步** 应用（只执行 DDL，**不复制数据**）。

限制（界面上也有说明）：

- 只同步**字段、主键与索引**；外键、触发器、函数不会被创建；
- 多余的字段 / 索引默认**只提示不删除**，需要显式勾选"允许删除"；
- 源与目标必须在同一个连接里（跨实例同步请先备份再导入）。

## 服务器页

顶栏 **服务器**（需要先连接）。四个页签，按驱动与权限显示：

| 页签 | MySQL | PostgreSQL | SQLite |
| --- | --- | --- | --- |
| **状态** | 版本、运行时间、连接数、查询数、流量、库数 / 表数 | 连接数、事务数、缓存命中、库大小等 | 文件级信息（`foreign_keys`、`page_count`、`page_size` 等） |
| **变量** | 全部状态变量（497 项，可搜索） | 服务器设置 | 仅少量 pragma |
| **进程** | `SHOW PROCESSLIST`，可终止 | `pg_stat_activity`，可 `pg_cancel_backend` / `pg_terminate_backend` | 无 |
| **账号** | 用户列表、权限矩阵、授权语句预览、新建 / 编辑 / 删除账号 | 角色属性、角色成员、权限矩阵 | 无（明确提示不支持） |

- 权限不足时不会假装成功：会显示"当前数据库账号没有执行 X 所需的服务器权限"，
  并提示让 DBA 授权后点"刷新"（不需要重新连接）。
- 加载超时会明确显示"8 秒内数据库没有返回"，不会一直转圈。

## 查询历史

顶栏 **工具 → 历史记录**（不需要连接）。

- 每条记录：时间、状态（ok / failed）、数据库、语句数、耗时、SQL 预览；
- 每页 50 条，Rust 侧 limit/offset 分页；
- **重跑**：把该条 SQL 放回控制台执行（**被截断的记录禁止重跑**，避免执行不完整的 SQL）；
- **复制 / 完整 SQL**：查看完整语句（单条上限 32 K 字符，超出部分会标注截断）；
- **清空历史**：需确认。

> 历史文件在启动时会自动压缩旧内容，并保留 `.bak`，避免长期使用后文件无限膨胀。

### 数据与卸载

卸载前想知道「我的连接配置在哪、删了会不会丢」，看这一块：

- 打开设置即扫描一次数据目录，显示**真实路径**、**共几个文件 / 多大**，以及顶层内容
  （`connections.json`、`query_history.json`、`settings.json`、`backups/` …）；
- **打开数据目录**：在系统文件管理器里定位该目录；
- **执行清空…**：二次确认后删除目录内的**全部**文件（连接配置含密码、查询历史、设置、
  备份），**不可撤销**。清空后需要重启应用才完全生效 —— Rust 侧的连接池、备份索引
  还指着刚被删掉的文件，所以应用不会自作主张替你退出。

各平台卸载时对用户数据的处理不同：

| 平台 | 卸载时会提示吗 | 用户数据 |
| --- | --- | --- |
| Windows（NSIS 安装包） | **会**：弹窗询问是否一并删除，默认「否」 | 选「是」删除；选「否」保留。静默卸载（`/S`，含「应用和功能」）**一律保留**，要删需显式加 `/DELETEUSERDATA` |
| macOS（拖到废纸篓 / 删除 .app） | 不会（系统没有卸载钩子） | 保留，需手动删除数据目录 |
| Linux（deb / rpm / AppImage） | 不会 | 保留，需手动删除数据目录 |

卸载行为矩阵与手动清理命令见 [../packaging/UNINSTALL.md](../packaging/UNINSTALL.md)。

### 检查更新 / 自动更新

- 设置页**只有「检查更新」按钮**，没有地址输入框：更新源固定在代码里
  （`lib/src/update_source.dart` 的 `kUpdateManifestUrl`），旁边一行只读说明
  "更新源：GitHub · L-Y-P/DBPilot"。
- 点按钮 → 读取
  `https://raw.githubusercontent.com/L-Y-P/DBPilot/main/update.json` →
  与当前版本做数值比较：
  - **有新版本：自动下载并安装，完成后应用自动重启**（与市面上桌面应用一致）：
    优先用清单里的 `assets` 地址，缺失时回退 GitHub Release 命名约定
    （`releases/download/v<版本>/DBPilot-<版本>-<平台包>`）。
    - macOS：下载 macos.zip，解压后用 ditto 原地替换 .app，再重新打开；
    - Windows：下载 setup.exe，退出前启动 NSIS 静默安装（`/S`，会请求管理员权限），
      安装完重新打开；
    - Linux：仅 AppImage 支持原地更新（替换 $APPIMAGE 后重启）；deb/rpm 安装方式
      会提示用下载地址手动更新。
    - 下载有进度条与「取消」；失败显示原因并提供「重试自动更新」+「下载地址」手动兜底。
  - 已是最新："已是最新版本"；
  - 失败：显示具体原因（HTTP 状态码 / 清单不是合法 JSON / 缺 `version` / 超时 /
    下载不完整 / 安装失败），不会静默失败。
- 安全：只接受 http(s) 地址；下载先写 `.part`，Content-Length 校验通过后才改名安装；
  安装路径不可写时会回滚并提示手动更新。
- 发版流程见 [RELEASE.md](RELEASE.md)。

## 数据存放与安全

数据目录（文件 0600、目录 0700，全部经 `secure.rs` 原子写）：

| 平台 | 目录 |
| --- | --- |
| macOS | `~/Library/Application Support/com.rustmyadmin.rustMyadminDesktop/` |
| Windows | `%APPDATA%\com.rustmyadmin\DBPilot\` |
| Linux | `~/.local/share/com.rustmyadmin.rust_myadmin_desktop/` |

| 文件 | 内容 |
| --- | --- |
| `connections.json` | 连接配置（**含密码**） |
| `settings.json` | 语言、主题、性能开关、备份目录、窗口尺寸 |
| `query_history.json` | 查询历史（每条 ≤32 K 字符） |
| `backups/` | 备份文件与 `index.json` |

安全边界：

- 应用是**本地单用户**工具，没有登录；唯一的数据访问边界是每条连接的
  `only_db` / `hide_db`，在"列出对象"和"执行 SQL"两侧都会校验。
- 应用**不会也无法绕过数据库自身的权限**：所有操作都以你配置的那个数据库账号执行。
- 密码明文落盘（0600），**没有接系统钥匙串**。需要更强隔离时，请用最小权限账号，
  或用 SSH 隧道 + 服务端账号控制。
- 所有写盘都走"临时文件 → 收紧权限 → 原子 rename"，进程中途崩溃不会留下半截文件。
- **卸载不会自动删除上表这些文件**：它们不在程序目录里，卸载程序清不到。要清掉请用
  **设置 → 数据与卸载 → 执行清空…**，或卸载后手动删除数据目录（Windows 安装包在
  卸载时会询问，默认保留）。

## 常见问题

**连不上 MySQL，提示认证插件 / TLS？**
MySQL 8 默认 `caching_sha2_password`，需要 TLS 或服务端配置允许明文。先在 SSL 页签试
`require`；仍然失败时看错误里是否带 1045（账号密码错误，只有这种情况才会给 TLS 建议）。

**PostgreSQL 看不到某些 schema / 库？**
用的是 `has_schema_privilege(USAGE)` / `has_database_privilege(CONNECT)` 过滤。
当前账号没有权限就不会显示，这是预期行为。

**SQLite 只显示了一部分文件？**
SQLite 默认最多 10 个 `ATTACH`。超出的文件会在侧栏提示"另有 N 个未打开"；
把连接目录改小一些，或分多个连接。

**导入大文件时界面卡住？**
导入是后台任务，界面只在轮询进度；如果进度长时间不动，点 **取消**，
然后检查"第 N 行"的错误提示（通常是分隔符 / 引号规则不对）。

**表格里的大字段只显示前 120 个字符？**
"大字段延迟加载"默认开启（设置 → 性能）。双击单元格仍可看全文；
需要一次性全显示就关掉这个开关。

**为什么没有 Linux 预编译包？**
目前只在 macOS / Windows 上出了包，Linux 可以按 README 的编译章节自行构建。

**更新检查一直失败？**
先确认能访问 `raw.githubusercontent.com`（部分网络环境会拦截）；错误面板会给出
具体原因（HTTP 状态码 / JSON 解析 / 超时），据此判断是网络还是清单问题。
